# Ролевая модель и авторизация

## Роли пользователей

- **Администратор** (`is_admin=True`): имеет полный доступ ко всем действиям, может модерировать пользователей, новости и комментарии.
- **Автор** (`is_author=True`): может создавать новости, редактировать и удалять собственные новости, управлять комментариями под ними.
- **Обычный пользователь**: может читать новости, оставлять комментарии и редактировать/удалять только собственные комментарии.

## Аутентификация

Поддерживаются две стратегии входа:

1. **Логин и пароль** — регистрация формирует Argon2-хеш пароля. При входе API проверяет соответствие и выдает пару токенов (access + refresh).
2. **GitHub OAuth** — перенаправление на GitHub, получение кода и обмен на профиль. Если пользователь отсутствует, создается новый аккаунт и привязывается `github_id`.

## Токены и сессии

- Доступ выдаётся по JWT (HS256). В payload помещается идентификатор пользователя и идентификатор сессии.
- Refresh токен хранится только на клиенте, но активные сессии фиксируются в Redis с привязкой к `user_agent`.
- Для обновления токенов требуется живая сессия; при логауте сессия удаляется из Redis.

## Проверка прав

- Middleware зависимость `role_required` проверяет права на основе флагов пользователя.
- Для операций над конкретной новостью/комментарием используется зависимость, которая вытягивает сущность и удостоверяется в праве пользователя (`author` или `admin`, либо владелец ресурса).
